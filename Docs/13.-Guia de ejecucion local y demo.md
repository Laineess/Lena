# 13. Guía de ejecución — local, demo y pruebas en tu equipo

**Proyecto:** Leña
**Para:** correr el sistema en tu PC, enseñarlo a un negocio y probarlo desde otro dispositivo.

Todavía no hay tablets. Esta guía usa tu PC como servidor y el navegador (de la PC o del teléfono) como cliente.

---

## 1. Qué necesitas instalar (una sola vez)

| Herramienta | Para qué | Cómo comprobar |
|---|---|---|
| **Docker Desktop** | La base de datos (Postgres) corre en un contenedor | `docker --version` |
| **Node 22+** | El servidor y la app | `node --version` |
| **pnpm 9** | Gestor de paquetes | `npm i -g pnpm` → `pnpm --version` |

Abre Docker Desktop **antes** de empezar (el ícono de la ballena debe estar corriendo).

---

## 2. Arrancar todo en local (5 pasos)

Desde la carpeta del proyecto (`Desktop/Leña`), en una terminal:

```bash
# 0. Crear tu archivo .env (la primera vez, OBLIGATORIO)
#    Copia la plantilla. Sin .env, la base arranca sin contraseña y falla.
cp .env.example .env
#    En PowerShell de Windows:  copy .env.example .env

# 1. Instalar dependencias (la primera vez)
pnpm install

# 2. Levantar la base de datos (Postgres en el puerto 5434)
pnpm db:up

# 3. Crear las tablas y datos de ejemplo
pnpm db:migrate
pnpm db:seed
pnpm --filter @lena/api seed:auth   # credenciales de prueba con contraseñas reales

# 4. Arrancar el servidor (API) — déjalo corriendo en esta terminal
pnpm --filter @lena/api dev
```

En **otra terminal** (deja la anterior abierta):

```bash
# 5. Arrancar la app (PWA)
pnpm --filter @lena/pwa dev
```

Abre en el navegador: **http://127.0.0.1:5173**

> Nota: la base local usa el puerto **5434**, no el 5432, porque tu PC ya tiene otro PostgreSQL en el 5432. No hay que hacer nada, ya está configurado.

---

## 3. Credenciales de prueba

**Mesero y cocina** entran en 2 pasos: **clave de sucursal** → elegir usuario → **PIN**.

| Quién | Cómo entra | Ve |
|---|---|---|
| **Ana** (mesera, Centro) | clave **CENTRO** → Ana → PIN **481920** | Captura de comandas |
| **Luis** (mesero, Centro) | clave **CENTRO** → Luis → PIN **481922** | Captura de comandas |
| **Miguel** (cocina, Centro) | clave **CENTRO** → Miguel → PIN **481921** | Tarjetas de cocina |
| **Dueño (superadmin)** | "Soy dueño o administrador" → **super@lena.local** / **ClaveSuper2026x** | Escritorio **global**: todas las sucursales, alta de sucursales y administradores |
| **Admin Centro** | idem → **admin@lena.local** / **ClaveAdmin2026x** | Escritorio de **su** sucursal (Centro) |
| **Admin Norte** | idem → **norte@lena.local** / **ClaveAdmin2026x** | Escritorio de **su** sucursal (Norte) |

El seed trae **2 sucursales**: **Centro** (clave `CENTRO`) y **Norte** (clave `NORTE`). La clave se ve en el escritorio de gestión (tarjeta de la sucursal y en *Inicio* del administrador). Al crear una sucursal nueva, su clave se genera sola.

> **Superadmin vs administrador:** el dueño (superadmin) ve todas las sucursales, crea sucursales y da de alta administradores. Cada administrador gestiona **solo** su sucursal. El escritorio usa tema oscuro (negro/rojo/dorado). El **turno de caja** lo abre/cierra el **administrador** (en *Inicio*), no el mesero.

## 4. Recorrido para enseñarlo a un negocio

1. **Abrir el día** (admin): entra como **Admin Centro**, en *Inicio* captura el fondo (p. ej. 1000) → "Abrir turno". Sin turno abierto, los meseros no pueden cobrar.
2. **Levantar una comanda** (mesero): entra con clave **CENTRO** → Ana → PIN. Elige "Para llevar", toca `+` en unos productos, "ENVIAR A COCINA". Aparece el identificador para vocear (**A-1**).
3. **Verla en cocina:** en otra pestaña/ventana, clave **CENTRO** → Miguel (cocina). La comanda aparece como tarjeta con cronómetro. Toca ✓ para marcarla lista.
4. **Cobrar:** de vuelta como Ana, toca ☰ (comandas), en la comanda toca "Cobrar", elige efectivo, un atajo ($100), mira el **cambio**, "COBRAR ✓".
5. **Ver la caja:** como Admin Centro, ve **Caja del día** (venta de hoy + lista de comandas; clic en una abre su detalle) y **cierra el turno** en *Inicio* (efectivo contado → esperado y diferencia).
6. **El control antifraude:** en el admin, **Merma** — la tabla que detecta al mesero que cancela de más.

**Sin internet:** apaga el Wi-Fi a media captura. El mesero sigue trabajando; al volver la red, todo se sincroniza solo. Ese es el punto fuerte del sistema.

## 5. Probarlo desde tu teléfono o tablet (misma red Wi-Fi)

Para que otro dispositivo de tu casa abra la app apuntando a tu PC:

```bash
# Arranca la PWA escuchando en toda la red (no solo en la PC)
pnpm --filter @lena/pwa dev -- --host 0.0.0.0
```

Averigua la IP de tu PC en la red local:

- Windows: `ipconfig` → busca "Dirección IPv4" (algo como `192.168.1.50`).

Desde el teléfono (en el mismo Wi-Fi), abre: **http://192.168.1.50:5173** (con tu IP).

> **Límite conocido:** sobre `http` en red local, el navegador **no** instala la PWA ni activa el modo offline completo (eso exige `https`). Para una demo de las pantallas y el flujo, funciona perfecto. Para probar el **offline real y la instalación como app**, ve al punto 6.

---

## 6. Correrlo como en producción (para instalarlo como app / ofrecerlo de verdad)

En un servidor con un **dominio** (tu VPS), con Docker:

```bash
# En el servidor, dentro de la carpeta del proyecto:
# 1. Pon tu dominio en el Caddyfile (reemplaza lena.ejemplo.mx)
# 2. Crea un .env de producción (contraseñas reales, DATABASE_URL_APP apuntando a postgres:5432)
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Caddy saca el certificado HTTPS solo. Con eso:

- Las tablets abren `https://tu-dominio` y **la instalan como app** (menú de Chrome → "Instalar app").
- Funciona el **modo offline** completo (service worker + IndexedDB).

Desde tu PC de desarrollo puedes desplegar en un comando:

```bash
pnpm deploy   # entra al VPS por SSH, construye, migra y levanta (ver scripts/deploy.sh)
```

## 7. Comandos útiles

| Comando | Qué hace |
|---|---|
| `pnpm db:reset` | **Borra todo** y vuelve a levantar la base limpia (luego re-corre migrate/seed) |
| `pnpm -r test` | Corre todas las pruebas (~226) |
| `pnpm typecheck` · `pnpm lint` | Revisa tipos y estilo |
| `BACKUP_PASSPHRASE=… bash scripts/backup.sh` | Respaldo cifrado de la base |
| `BACKUP_PASSPHRASE=… bash scripts/restaurar.sh <archivo> lena_restore` | Simulacro de restauración |

## 8. Si algo falla

| Síntoma | Causa probable | Solución |
|---|---|---|
| `Database is uninitialized and superuser password is not specified` | No creaste el `.env` (o quedó sin `POSTGRES_PASSWORD`) | `cp .env.example .env`, luego `pnpm db:reset` para recrear la base |
| `ports are not available: 5434` | Ya hay algo en ese puerto | Cambia `POSTGRES_PORT` en `.env` a 5435 y ajusta las dos URL |
| El login no responde | El API no está corriendo | Revisa la terminal del paso 4 |
| La app carga pero no entra | La base no tiene credenciales | Corre `pnpm --filter @lena/api seed:auth` |
| Docker "cannot connect" | Docker Desktop está cerrado | Ábrelo y espera a que arranque |

## 9. Entrar en una tablet (clave de sucursal)

El mesero/cocina entra en 2 pasos: escribe la **clave de la sucursal** (p. ej. `CENTRO`), elige su usuario y teclea su PIN. La clave se recuerda en el dispositivo, así que al cerrar sesión vuelve directo a la lista de usuarios. El superadmin puede **rotar la clave** desde Sucursales si se filtra o cambia de personal.

## 10. Compatibilidad de navegadores — Safari / iPad (evaluación)

**Sí corre en Safari**, con condiciones. El objetivo principal es la **Samsung Galaxy Tab A11 (Android/Chrome)**; el iPad es una alternativa viable en **iPadOS/iOS 16.4 o superior** (2023+).

| Tema | En Safari/iOS | Nota |
|---|---|---|
| **PWA / "app"** | ✅ Funciona en pantalla completa | iOS **no** muestra botón de instalar: se agrega manual desde *Compartir → Agregar a inicio* (2 toques). Ya se pusieron los `meta` de Apple para pantalla completa. |
| **Offline (Service Worker + IndexedDB/Dexie)** | ✅ Soportado | ⚠️ iOS **borra IndexedDB tras ~7 días sin abrir la app** (ITP). Para un POS de uso diario no es problema; si una tablet queda guardada una semana, su cola offline se vacía (se sincroniza sola al reconectar antes de eso). |
| **Estilos (Tailwind v4)** | ✅ en **16.4+** | Tailwind v4 usa CSS moderno; **iPads con iOS < 16.4 no se ven bien**. Es el requisito más duro. |
| **WebSocket (sync en vivo)** | ✅ | Sin cambios. |
| **Sonido de cocina (Web Audio)** | ✅ | iOS exige un toque para "desbloquear" el audio; ya se hace al primer toque. |
| **Cámaras/impresora/hardware** | n/a | El MVP no usa hardware nativo. |

**Datos para la presentación:** `pnpm db:seed-demo` llena **8 semanas** (56 días) de la sucursal **Centro** con ventas, cancelaciones (control antifraude), cortes, gastos e insumos — así todos los reportes y la **compra sugerida** ya muestran números reales. Entra como **Admin Centro** (`admin@lena.local`) o como dueño filtrando Centro. Es idempotente: re-córrelo para regenerar.

**Logs / errores:** el API escribe todo (peticiones y errores con su stack) en `apps/api/logs/lena-AAAA-MM-DD.log` (una línea JSON por evento). Para ver errores: `grep '"level":50' apps/api/logs/*.log` (nivel 50 = error, 60 = fatal). Se puede seguir en vivo con `tail -f`.

---

**Veredicto:** para demo y piloto, **iPad con iPadOS ≥ 16.4 sirve**. Recomendación: usar **añadir a pantalla de inicio** (no la pestaña del navegador) para modo app y offline reales, y no dejar una tablet sin abrir más de una semana con comandas sin sincronizar. El HTTPS del despliegue (Caddy) es requisito para instalar la PWA y para el offline completo, igual que en Android.
